# 测试数据说明

`5_TestData` 保存了不同时期通过 VOFA+ 记录的 CSV。早期文件的列名通常为 `I0`～`I9`，且不同固件阶段的字段映射可能不同，使用前必须结合测试日期和对应源码确认。

## 当前主固件字段

当前 F407 主工程在数传电台模式下发送 10 个浮点字段：

| CSV 列 | 当前含义 | 建议单位 |
| --- | --- | --- |
| I0 | 换挡电机位置 | ° |
| I1 | 换挡电机力矩回传 | N·m，需按电机协议确认 |
| I2 | 换挡电机温度 | °C |
| I3 | ECU 原始档位 | 档 |
| I4 | 稳定处理后的档位 | 档 |
| I5 | 目标档位 | 档 |
| I6 | ECU 电压 | V |
| I7 | 发动机转速 | r/min |
| I8 | 加速踏板开度 APPS | % |
| I9 | 冷却液温度 CLT | °C |

字段来源为 `SA_E_Shift.c` 中的 `Radio_Data_Send`。如果修改发送顺序，应同步更新本文件。

## 已有文件的限制

- 多数历史文件没有记录固件提交哈希。
- 一部分文件沿用通用列名，无法只靠 CSV 判断字段。
- `20250306.csv` 的表头存在编码异常。
- 大文件未裁剪为具体换挡事件，外部贡献者难以快速复现。
- 目前没有统一的采样率、车辆状态和成功/失败标签。

因此，现有数据适合作为开发档案，不应直接用于发布定量性能结论。

## 新测试的命名与元数据

推荐文件名：

```text
YYYYMMDD-HHMM_场景_结果_固件短哈希.csv
```

例如：

```text
20260730-1530_台架二升三_成功_a1b2c3d.csv
```

每个数据文件应配套同名 Markdown 或在测试日志中记录：

- 固件提交哈希。
- PCB、机械与电机版本。
- 电机固件、ID、速度和扭矩限制。
- ECU 固件与 CAN 配置。
- 采样率和字段单位。
- 发动机是否运行、当前转速和车辆状态。
- 测试目标、成功条件和实际结果。
- 异常现象及下一步处理。

## 建议的公开数据集

后续可从完整日志中裁剪三类小样例：

1. 正常升档和降档。
2. 档位信号经过短暂空档。
3. 换挡超时、未入档或电机力矩异常。

每个样例控制在数秒到数十秒，并提供标注区间。完整原始日志可通过 GitHub Release 或独立数据归档提供，仓库中只保留便于测试和绘图的小样本。
