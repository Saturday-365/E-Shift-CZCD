# 测试记录规范

历史台架与出车 CSV 已从主分支移除。需要追溯原始记录时，请查看开源化整理前的 [GitHub 提交 `0a7fb9e`](https://github.com/Saturday-365/E-Shift-CZCD/commit/0a7fb9e37e109e1c96eb0db8fb1200f69377ce26)；本地仓库也保留备份分支 `codex/backup-before-opensource-20260730`。

移除原因是这些记录缺少统一的固件版本、采样率、车辆状态和结果标注，不适合直接作为可复现数据集。下列规范用于后续测试，不代表旧数据已经按此补全。

## 当前主固件字段

当前 F407 主工程在数传电台模式下发送 10 个浮点字段：

| 发送序号 | 当前含义 | 建议单位 |
| --- | --- | --- |
| I0 | 换挡电机位置 | ° |
| I1 | 换挡电机力矩回传 | N·m，需按电机协议确认 |
| I2 | 换挡电机温度 | °C |
| I3 | ECU 原始档位 | 档 |
| I4 | 稳定处理后的档位 | 档 |
| I5 | 目标档位 | 档 |
| I6 | ECU 电压 | V |
| I7 | 发动机转速 | r/min |
| I8 | 加速踏板开度 APPS | % |
| I9 | 冷却液温度 CLT | °C |

字段来源为 `SA_E_Shift.c` 中的 `Radio_Data_Send`。如果修改发送顺序，应同步更新本文件。

## 历史记录的限制

- 多数历史文件没有记录固件提交哈希。
- 一部分文件沿用 `I0`～`I9` 等通用列名，无法只靠 CSV 判断字段。
- 个别文件的表头存在编码异常。
- 大文件未裁剪为具体换挡事件，外部贡献者难以快速复现。
- 目前没有统一的采样率、车辆状态和成功/失败标签。

因此，历史数据只适合作为开发档案，不应直接用于发布定量性能结论。

## 新测试的命名与元数据

推荐文件名：

```text
YYYYMMDD-HHMM_场景_结果_固件短哈希.csv
```

例如：

```text
20260730-1530_台架二升三_成功_a1b2c3d.csv
```

每个数据文件应配套同名 Markdown，或在测试日志中记录：

- 固件提交哈希。
- PCB、机械与电机版本。
- 电机固件、ID、速度和扭矩限制。
- ECU 固件与 CAN 配置。
- 采样率和字段单位。
- 发动机是否运行、当前转速和车辆状态。
- 测试目标、成功条件和实际结果。
- 异常现象及下一步处理。

## 数据发布方式

后续可从完整日志中裁剪三类小样例：

1. 正常升档和降档。
2. 档位信号经过短暂空档。
3. 换挡超时、未入档或电机力矩异常。

每个样例控制在数秒到数十秒，并提供标注区间。完整原始日志建议通过 GitHub Release 或独立数据归档发布，同时注明对应提交、文件校验值、字段定义和许可证。只有体积较小、元数据完整且可用于自动化测试的样本才应进入主仓库。
