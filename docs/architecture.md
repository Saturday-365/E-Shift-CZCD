# 系统架构说明

## 数据链路

系统使用 STM32F407VET6 连接车辆 ECU、CyberGear 换挡电机、方向盘拨片和数传设备。

| 接口 | 当前用途 | 参数 |
| --- | --- | --- |
| CAN1 | CyberGear 换挡电机 | 1 Mbit/s，PA11 RX、PA12 TX |
| CAN2 | ECU 数据接收 | 500 kbit/s，PB12 RX、PB13 TX |
| USART1 | 调试/通信预留 | PA9 TX、PA10 RX |
| USART2 | 调试/通信预留 | PD5 TX、PD6 RX |
| USART3 | RS232/数传链路 | PD8 TX、PD9 RX |
| 升档输入 | 方向盘拨片 | PE9 |
| 降档输入 | 方向盘拨片 | PB1 |
| 升档输出 | ECU 断火请求 | PB4 |
| 降档输出 | ECU 补油请求 | PB5 |

CAN 位时序和引脚由 CubeMX 生成，适配其他硬件时应在 `.ioc` 中修改。

```text

├─ main.c                  初始化、主循环、定时器回调
└─ can.c/gpio.c/...        CubeMX 生成的外设配置

Sourse_Library/

│  ├─ SA_E_Shift.c         换挡动作、档位稳定、超时处理
│  ├─ SA_CANDataprocess.c  ECU CAN 数据解析

├─ 3_SA_Starup/            公共初始化

```

## 当前换挡流程

升档流程：

1. 检查当前档位是否允许升档。
2. 拉高升档输出信号。
3. 根据当前档位查询换挡电机目标角度。
4. 发送 CyberGear 位置指令。
5. 等待目标档位或超时条件。
6. 电机回零并撤销升档输出。

降档流程与之类似，完成后可产生降档输出信号。

当前实现仍包含阻塞式 `while` 等待。后续状态机应拆分为“空闲、请求、等待 ECU、执行、确认、回零、完成、故障”等状态，并由周期任务推进。

## 车辆相关参数

以下参数目前位于 `SA_E_Shift.c`，更换车辆、发动机、拉杆或电机后必须重新标定：

- 各档位升档和降档角度。
- 换挡电机最大速度和最大扭矩。
- 升档断火等待时间。
- 降档补油等待时间。
- 换挡超时时间。
- 档位稳定连续采样阈值。

参数调整必须保留测试条件、数据文件和对应固件提交，避免只记录“感觉更好”。

## 失效场景

目前最值得补充自动测试和保护的场景包括：

- CAN 数据超时或连续丢帧。
- 档位数据非法跳变。
- 电机未到位或目标档位未确认。
- 电机过温、过流或错误码。
- 拨片粘连、重复触发或同时触发。
- MCU 重启后当前档位未知。
- 升降档请求超出 0～6 档范围。
